# Usage API Documentation

This document provides an overview and usage examples for the provided APIs. Each API endpoint includes a description,
request parameters, and Python code examples to help you integrate these APIs into your applications.

## Table of Contents

- [Authentication](#authentication)
- [Endpoints](#endpoints)
    - [Usage Fetch](#usage-fetch)

## Authentication

All endpoints require two URL parameters for authentication:

- `magic_id`: A unique identifier for the magic resource.
- `access_key`: An access key associated with the magic resource.

## Endpoints

### Usage Fetch

Fetches usage data based on provided filters.

- **URL**

  ```
  POST /magics/<magic_id>/<access_key>/usage/fetch
  ```

- **Request Headers**

  ```
  Content-Type: application/json
  ```

- **Request Body**

  ```json
  {
    "chunk": 1,  // Optional, default is 1
    "filters": {
      "status__in": ["status1", "status2"],       // Optional
      "status__not__in": ["status3", "status4"],  // Optional
      "time__before": 1638316800000000,           // Optional, in microseconds
      "time__after": 1635724800000000             // Optional, in microseconds
    }
  }
  ```

- **Response**

  ```json
  [
    {
      "ref": "job_reference",
      "time": 1638316800000000,
      "magic": "magic_id",
      "request": { /* request data */ },
      "response": { /* response data */ },
      "status": "status_code",
      "duration": 10,
      "state": "done | failed | cancelled | running | waiting | initializing"
    }
    // ... more items
  ]
  ```

- **Field Descriptions**:
    - `ref`: A reference identifier for the job, excluding the first five characters.
    - `time`: The timestamp when the job was last updated, in microseconds.
    - `magic`: The unique identifier of the magic resource.
    - `request`: The original request data associated with the job.
    - `response`: The response data generated by the job.
    - `status`: The status code representing the job's current status.
    - `duration`: The duration between the earliest and latest timestamps in the job's timing data, in seconds.
    - `state`: The current state of the job, which can be one of the following:
        - `waiting`: The job is waiting to be processed.
        - `initializing`: The job is in the process of being set up.
        - `running`: The job is currently in progress.
        - `cancelled`: The job has been cancelled.
        - `done`: The job has been successfully completed.
        - `failed`: The job has failed.


- **Example Python Usage**

  ```python
  import requests

  url = "https://v226251f-b3f1-db.cablo.io/magics/<magic_id>/<access_key>/usage/fetch"
  headers = {
      "Content-Type": "application/json"
  }
  payload = {
      "chunk": 1,
      "filters": {
          "status__in": [200, 401],
          "time__after": 1635724800000000
      }
  }

  response = requests.post(url, json=payload, headers=headers)

  if response.status_code == 200:
      data = response.json()
      print(data)
  else:
      print(f"Error: {response.status_code}")
  ```

## Notes

- Replace `<magic_id>` and `<access_key>` in the URLs with your actual `magic_id` and `access_key`.
- All timestamps are in UNIX time (seconds since the epoch).
- All time-related values in request bodies or responses are expected to be in microseconds (`time` fields) or
  seconds (`due` fields).
- Ensure that you handle HTTP status codes appropriately in your applications.
